Set up SSH jump access

Use an SSH key to reach SoC print servers from COM2 and other NUS campus locations without direct access. When you are on a direct SoC connection, the macOS app can enroll your selected key automatically or create a protected key for you. You can also choose your own key and register it manually. Once set up, the jump host works with the app and with SSH from Terminal or Command Prompt.

1. Create or choose a key

In the app’s Account → SSH key section, choose an existing private key or create one. For guided setup, choose Set up automatically when the app detects direct SoC access. The app creates an encrypted Ed25519 key with a random passphrase stored in macOS Keychain, or uses the key you already selected.

To create a separate key in Terminal instead:

ssh-keygen -t ed25519 -f ~/.ssh/print_soc_ed25519 -C "SimplyPrint @ SoC"

Choose a strong passphrase. If the file already exists, decline overwriting it and choose another filename. Keep the private key on your Mac.

2. Copy only the public key

In the app, choose Copy public key. For a Terminal-created key:

pbcopy < ~/.ssh/print_soc_ed25519.pub

A public key is one long line beginning with a type such as ssh-ed25519. The file ending in .pub is public. Never paste or upload the private key.

For an existing private key without a matching .pub file, derive the public part locally:

ssh-keygen -y -f "/path/to/your/private-key" | pbcopy

3. Enroll automatically or register manually

Automatic setup is available after a direct connection to SoC. The app checks your selected key using key-only SSH authentication. If it is rejected, you can enroll that key first or choose another. The app reads the current jump-key fingerprints and includes every existing key plus your selected key. It searches for matching public-key lines in the selected key’s .pub file, ~/.ssh, and its managed key folder. If a registered key is missing, it asks you to paste the matching public-key line before continuing. It stops if the list changes or any registered key cannot be represented.

To register manually, use your SoC username in place of YOUR_SOC_USERNAME:

ssh YOUR_SOC_USERNAME@skeys.comp.nus.edu.sg

Verify the host fingerprint with SoC before trusting it. Sign in with your SoC password, then follow the service’s on-screen instructions.

  1. Review the existing jump-key list first. Retain any keys you still use.
  2. Select the jump option. Paste your public key as one complete line. If the service replaces the list, include the existing keys you want to retain as well.
  3. When prompted to finish key input, press Control D. Review the saved list before leaving.

The connection, jump option, and Control-D input are described in the SoC jump-host setup walkthrough. Follow the current SSH Key Service guide if its prompts differ. DocHub may require campus network access.

4. Test and use the registered key

If you created ~/.ssh/print_soc_ed25519, add the following block to ~/.ssh/config. For an app-created key, replace the IdentityFile path with the private key selected in Account. Keep existing configuration; do not replace the whole file.

Host sjump.comp.nus.edu.sg
    User YOUR_SOC_USERNAME
    IdentityFile ~/.ssh/print_soc_ed25519
    IdentitiesOnly yes

Then test the connection:

ssh -J YOUR_SOC_USERNAME@sjump.comp.nus.edu.sg YOUR_SOC_USERNAME@stu.comp.nus.edu.sg

Enter the key’s passphrase when requested. The destination server may also ask for your SoC password. In SimplyPrint @ SoC, choose the same private key, enter its passphrase, Save, and Connect. Use exit to leave a Terminal session.

Troubleshooting

Permission denied
Confirm that the public key appears in SoC’s jump-key list and that you selected its matching private key. Check Unix access and current network/VPN requirements.
Wrong passphrase
The private-key passphrase is separate from your SoC account password. A forgotten passphrase cannot be recovered; create and enroll a replacement key in the app, or follow the manual setup steps.
DocHub or the key service is unreachable
Try the network required by SoC’s jump-host guide. Contact SoC Technical Services if access still fails.

Automatic enrollment submits the complete merged public-key list because the SoC service replaces the jump-key list. The app verifies the resulting fingerprints and then tests jump access. It stops rather than submit a partial list when an existing public key is missing or the configuration changes. Manual registration remains available through SoC’s SSH Key Service.
